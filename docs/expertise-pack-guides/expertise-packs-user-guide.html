Preparing, Activating & Running an ARIA Expertise Pack

An Expertise Pack packages a practice's custom SDLC process, engineering standards, deliverable templates, specialist personas, skills, and evaluation rubrics into a Markdown + JSON-only folder. Agents read the compact manifest index (~1.4k tokens) to route work and open standards like STD-SEC-2026 strictly on the stages that need them.

3. How to Validate, Install & Activate the Pack

Scaffold or validate from the terminal, then activate globally for yourself or commit directly into a team repository.

1. Validate, Test & Package (CLI)

Run the bundled pack tool before distributing or installing:

# 1. Validate manifest schema, markers, tool ceiling & token cost
python extension/runtime/tools/plugins/plugin.py validate ./regulated-sdlc

# 2. Run positive + negative prompt routing assertions
python extension/runtime/tools/plugins/plugin.py test ./regulated-sdlc

# 3. Optional: build deterministic archive with SHA256SUMS
python extension/runtime/tools/plugins/plugin.py pack ./regulated-sdlc --out dist/

2. Four Ways to Activate in VS Code

  • Mission Control UI (User-wide): Open Skills & packs → Install a pack…, pick your folder, .ariaplugin / .hveplugin file, Git URL, or organization index, confirm the SHA-256 & tool list, and click Reload Window.
  • Workspace-Committed (Zero install step): Commit the folder at plugins/regulated-sdlc/ in your repo. ARIA discovers, renders, and lists it as enabled automatically.
  • Team Requirement Prompt: Add aria.plugins.json (or frontier-hve.plugins.json) to the repo root so every teammate gets a 1-click Install prompt on open.
  • Built-In Example: Click Install example pack on Oracle Offering in Skills & packs to inspect a live working pack immediately.
Before installing any pack not pre-verified by your organization index, ARIA shows its exact publisher, sha256 content digest, and maximum tool ceiling. ✓ Rendered into chat.pluginLocations

4. Worked Enterprise Scenario: Regulated SDLC + Standard STD-SEC-2026

Suppose your enterprise introduces a mandatory production governance process requiring an InfoSec Threat & Controls Review and a UAT Environment Readiness Review governed by a new security standard.

Pack: regulated-sdlc 1.0.0

New Enterprise Standard: STD-SEC-2026

Zero-Trust Production Readiness & Data Classification Standard (stored in knowledge/std-sec-2026-standard.md):

  • §1 Data Tiering: Classify every payload as Tier-1 Restricted, Tier-2 Confidential, or Tier-3 Internal.
  • §2 Zero Static Secrets: Tier-1/2 services must enforce mutual TLS (mTLS) + workload identity; static API keys are forbidden.
  • §3 Audit Correlation: Emit immutable X-Audit-Correlation-Id logs on every state-mutating call.

Added Gate 1: infosec-review

Inserted immediately after build and delegated to pack persona regulated-sdlc:infosec-assessor:

  • Opens std-sec-2026-standard.md on demand.
  • Authors docs/compliance/INFOSEC-{slug}.md from template regulated-sdlc:infosecClearance.
  • Hard Gate: stage_evidence.py blocks marking the stage done until every STD-SEC-2026 section validates with zero {{FILL:...}} placeholders; sends back to build on violations.

Added Gate 2: uat-signoff

Inserted before release and delegated to pack persona regulated-sdlc:uat-release-reviewer:

  • Verifies UAT config parity, staging smoke suite logs, and a timed rollback rehearsal.
  • Authors docs/compliance/UAT-SIGNOFF-{slug}.md from template regulated-sdlc:uatSignoff.
  • Hard Gate + Rework: Requires both feature-checks passing and template-valid; failures trigger lifecycle.py rework back to build (capped at 2).

# STD-SEC-2026: Zero-Trust Production Readiness & Data Classification

1. **Data Classification (§1):** Every API must declare `Tier-1 Restricted`, `Tier-2 Confidential`, or `Tier-3 Internal` in its design and InfoSec clearance record.
2. **Zero Static Credentials (§2):** Tier-1 and Tier-2 workloads must authenticate via mTLS and short-lived workload identity tokens. Connection strings with embedded passwords or API keys fail InfoSec review automatically.
3. **Audit Correlation (§3):** Every state-changing request must require or mint `X-Audit-Correlation-Id` and emit structured actor/action/outcome audit events verified by an automated test.

6. How ARIA Auto & ARIA Collab Route & Execute via lifecycle.py

Toggle between ARIA Auto and ARIA Collab below to see the exact CLI commands and gate behavior when a user submits: “Build the customer wire-transfer approval API and take it to production under regulated SDLC.”

  1. 1

    Manifest Routing (lifecycle.py route) — Finds the Pack Without Reading Its Full Files

    Both agents save the prompt to .aria/asks/request.md and run lifecycle.py route. The router inspects plugins/regulated-sdlc/aria-plugin.json (and installed pack manifests), matches task_pattern + keyword regulated + workspace file compliance.yaml, and ranks regulated-sdlc:regulated-prod-sdlc #1 above built-in sdlc:

    python "{{RUNTIME}}/tools/loop/lifecycle.py" route .aria/asks/request.md
# → packs.matched: [{"name": "regulated-sdlc", "signals": 1, "why": ["task pattern matched 'regulated SDLC'", "signal compliance.yaml"]}]
# → lifecycles[0]: {"name": "regulated-sdlc:regulated-prod-sdlc", "pack": "regulated-sdlc"}
  2. 2

    Contracting with ARIA Auto (gates=ticked)

    ARIA Auto offers regulated-sdlc:regulated-prod-sdlc + @regulated-sdlc, writes plan.md, and asks you to tick which milestones should pause for human sign-off (you tick stage:infosec-review and stage:uat-signoff). It then binds the ask contract:

    python "{{RUNTIME}}/tools/loop/lifecycle.py" contract regulated-sdlc:regulated-prod-sdlc wire-transfer-api "ARIA Auto" .aria/asks/request.md @regulated-sdlc gates=ticked

    This copies std-sec-2026-controls and uat-readiness into .aria/skills/regulated-sdlc__*/ and records the pack's exact token share in plan.md.

    Contracting with ARIA Collab (Full Overlay or Mid-Project Stage Entry)

    ARIA Collab pauses at every persona hand-off — and if your team already built the API in an earlier ask and only needs the new regulated InfoSec + UAT stages before go-live, Collab scopes the contract to just those two stages and logs them in .aria/project/ledger.json:

    # Run only InfoSec Review + UAT Sign-off on an already-built service:
python "{{RUNTIME}}/tools/loop/lifecycle.py" contract regulated-sdlc:regulated-prod-sdlc wire-transfer-clearance "ARIA Collab" .aria/asks/request.md only=infosec-review,uat-signoff @regulated-sdlc
  3. 3

    Stage-Scoped Delegation Brief (lifecycle.py brief) — Injects STD-SEC-2026 On Demand

    When entering infosec-review, the orchestrator requests a stage brief for pack persona regulated-sdlc:infosec-assessor. Because std-sec-2026-standard lists "stages": ["design", "build", "infosec-review"], ask_packs.py injects its pointer now (and omits uat-environment-gate.md until uat-signoff):

    python "{{RUNTIME}}/tools/loop/lifecycle.py" brief "regulated-sdlc:infosec-assessor" stage=infosec-review
# Brief output includes:
# - Pack agent for this stage: regulated-sdlc:infosec-assessor (.../agents/infosec-assessor.agent.md)
# - Pack knowledge (open only when use-when applies): STD-SEC-2026 Zero-Trust & Data Classification Standard at .../knowledge/std-sec-2026-standard.md
  4. 4

    Templated Deliverable Initialization & Hard Evidence Gate (manage.py + stage_evidence.py)

    The pack persona initializes the custom template, audits the code against STD-SEC-2026, fills every required section, and validates it. Attempting to close the stage early is rejected automatically:

    python "{{RUNTIME}}/tools/templates/manage.py" init regulated-sdlc:infosecClearance --slug wire-transfer-api --session s1
# → writes docs/compliance/INFOSEC-wire-transfer-api.md

python "{{RUNTIME}}/tools/templates/manage.py" validate docs/compliance/INFOSEC-wire-transfer-api.md --session s1
python "{{RUNTIME}}/tools/loop/lifecycle.py" stage infosec-review done "Verified Tier-1 mTLS, workload identity & correlation logs"

    If UAT smoke checks or the rollback drill uncover a defect in uat-signoff, lifecycle.py rework uat-signoff "Rollback exceeded 30s target" reopens build (up to the "max": 2 cap).

  5. 5

    Human Sign-Off in Mission Control, Composite Evaluation & Provenance Report

    On Mission Control's Plan tab, each sign-off row links directly to docs/compliance/INFOSEC-wire-transfer-api.md and docs/compliance/UAT-SIGNOFF-wire-transfer-api.md. After you click Accept, ARIA runs the combined evaluation contract (coreShare: 0.7 + pack rubrics) and writes provenance.md:

    python "{{RUNTIME}}/tools/loop/lifecycle.py" report s1
# Writes .aria/asks/.../provenance.md with:
# - Pillars (quality, cost, tokens, latency, cache)
# - Stages & verified deliverables (INFOSEC-wire-transfer-api.md ✓, UAT-SIGNOFF-wire-transfer-api.md ✓)
# - Expertise packs token table (always-loaded manifest/skills vs on-demand STD-SEC-2026 & templates)
